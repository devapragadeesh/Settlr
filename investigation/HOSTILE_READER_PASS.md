The two deferred steps from `investigation/FINAL_GATE.md`, run now against the corrected

## What a hostile reader could attack, and the disposition of each

**SCORECARD.md, closing paragraph: "Nothing found here is worth fixing in the engine."**
Read alone, "here" is ambiguous between "on this scorecard" and "in this entire project" — the
second reading is false (D13, the GST axis, and the wrong-bank-side class are all open,
documented gaps elsewhere). **Fixed**: `corpus/scorecard.py` now emits "Nothing measured **on
this scorecard** is worth fixing in the engine," which survives being read alone.

**Every other SCORECARD.md row.** Checked row by row against the one-sentence test. Each
carries its denominator and scope inline in the same cell or the adjacent one ("of 275
`Verified`, 30 datasets"; "of 39 planted"; "a count, not a rate — the population is too small
for one"). None stands on its own without qualification; the qualification is always present
in the same row. Nothing else to fix here.

**README.md's THREE-SYSTEM-SUMMARY table and surrounding prose (the block Steps 1–2 actually
changed).** "coverage **57/168 (34%)**", "coverage **143/143 (100%), 25 record-contradicted**"
— each cell is self-scoped (the family and the record-contradicted count are both inline, not
deferred to a caption). The paragraph immediately below it ("Read coverage first…") explicitly
warns against the exact misreading a hostile reader would otherwise make — that coverage and
right/attempted answer different questions. This paragraph was written before this task and
is unchanged by it; re-read now, it still holds against the corrected numbers, because it
never states a specific figure, only the relationship between figures.

**README.md's SPLIT-FIGURES block ("701 rows are `ProvenUnmatched`… 4308 rows are
`OpenBreak`…").** Resolver-derived, not touched by the frozen-cascade fixes; re-checked anyway
per the task's instruction to pay particular attention near anything that moved. Both
sentences carry their own count and immediately state what it does and does not assert
("which assert nothing and are never gated on correctness"). Holds.

**README.md's commit-ordering closing list.** Lists the *founding* provenance chain (contract
→ seeds → data → baseline prediction → baseline results → …) as the original integrity
argument for the phase. It does not claim to be an exhaustive log of every commit since, and
reads that way on its own terms — a hostile reader attacking it as "incomplete" would be
attacking a claim the text does not make. No fix; recorded as considered and rejected.

**Everything the `grep` for absolute language surfaced** (`README.md` lines 16, 114, 116, 124,
128, 228, 246, 281, 296) was read in context: each "100%", "always", "perfect" is either a
component of a fully-qualified table cell (coverage percentages, always paired with the
attempted/total counts beside them) or an explicit statement about the *data*, not the
*engine* ("trusting the PSP **is perfectly calibrated there**" — scoped to "there", the
original-14 family, in the same sentence). None reads as an unqualified capability claim.

## What this pass did not do

It did not re-read all 411 lines of `README.md` sentence by sentence outside the zones named
above — the ordinary architecture, conventions, and setup sections were not re-litigated,
since nothing in Steps 1–2 touched them and this pass is scoped to what a hostile reader would
target after seeing numbers change. That is a real limit on this pass's coverage, stated
rather than implied.
